## Operational verification protocol (not performed on production)

1. **Two-person hold:** provision dedicated place/release permissions only after two named, independent principals and step-up are approved. Persist case ID, basis, scope, requester, co-approver and timestamps; audit both decisions. Lock the request row and recheck the lease/hold before any object claim or minimization. A hold committed during an S3 call cannot reverse that call; the following transition must stop. No current ADMIN is implicitly a hold principal.
2. **Owner/storage review:** require an authenticated, audited, fenced reclassification with provenance evidence, object ID, bucket/key, request lease and active-hold recheck. Requeue only after independent review of owner and topology. Direct SQL status changes are not an approved recovery operation.
3. **S3:** inventory each production bucket's versioning, noncurrent versions, replicas, lifecycle and ACL. Verify removal for the actual object topology before writing `VERIFIED`; HEAD 404 behind a delete marker is insufficient. A timeout or missing topology proof leaves `STORAGE_REVIEW_REQUIRED`.
4. **Backup/provider:** inventory snapshots by creation time, run a restore drill that replays the erasure ledger before allowing access, and separately obtain the provider's evidence or limitation for copies already submitted. Keep `BACKUP_UNVERIFIED` and `PROVIDER_UNVERIFIED` until verified in their own environments.
5. **Timing:** measure the approved 24-hour processing target under retry, hold, lease expiry and storage failures. Testcontainers, S3Mock and CI cannot establish production completion or the target.
