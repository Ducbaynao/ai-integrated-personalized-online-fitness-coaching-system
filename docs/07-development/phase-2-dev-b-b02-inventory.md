## 3. Đề xuất contract theo đợt, chỉ cho khoảng trống

1. **Đợt A — đã code trên nhánh, chưa merge hoặc nghiệm thu:** F05 typed Mobile client và query/UI dùng `commandKey` cho generate/accept (`openapi.yaml:12151-12247`), guard payload tổng quát và authority; F09 Admin import UI dùng endpoint JSON có sẵn và list array theo `page`/`size`. Bất nhất optional accept body và generation recovery vẫn chờ owner shared contract; không tạo command mới.
2. **Đợt B — cần Dev-A chốt shared contract trước khi code song song:** F06/F07 Spring tạo estimate draft từ text hoặc media reference đã authorize; GET draft/detail; Student sửa item identity, quantity/unit; POST selected-item confirm nguyên tử bằng `operationKey`, `expectedDraftRevision`, từng item ID/revision và catalog/conversion revision. Response gồm confirmed receipt, item IDs, nutrition snapshots/provenance, các item còn draft. Generation trả `ESTIMATE`, unknown quantity để `null`; calories/macros chỉ tính từ food DB sau identity + quantity + conversion hợp lệ. 409 có current revision/preview pointer, không tự commit lại giá trị mới. AI schema, OpenAPI và Flyway do owner tương ứng sửa cùng implementation sau review.
3. **Đợt C — sau source readiness:** F08 request/result INFORMATION với actor/subject, window/asOf, evidence, completeness, unknown/stale markers và run ID. Không endpoint Apply, không sửa Nutrition Goal. F10 danh sách Run cho feature mới chỉ mở rộng khi runtime thực sự ghi và kiểm được permission.
